# OthersTab調査機能 要件定義

## 📋 指示日時
2025-09-02

## 🎯 機能目的
入場予約システムの空き情報更新タイミングを正確に特定する

## 📝 元指示（そのままの記録）
調査方法はまずは60秒を4分割して取得していく。その際に直前の15秒刻みの取得結果と比較して変化していればその間(たとえば30秒と15秒で比較して15-30の間)が変化区間とわかる。念のため2周かけて同定する。次にまずその区間に通信の不安定性を加味して2秒と3秒ずつ拡大する(さっきの例なら13-33)、さらに5秒ずつ刻んで直前との比較で変化区間を見つける、これも念のため2周行う(この結果たとえば18-23が変化区間だとする)。次に2秒ずつ拡大した区間(たとえば16-25)で1秒刻みでapi実行して調査する、これも2周行う。最後に同定した1秒に2秒ずつ拡大した区間で1秒刻みで2周確認する。

## 📊 調査アルゴリズム詳細

### フェーズ1: 粗調査 (15秒刻み)
1. **60秒を4分割**して取得
   - 0秒、15秒、30秒、45秒でAPI実行
   
2. **隣接する15秒刻みの結果を比較**
   - 例: 30秒と15秒の結果を比較
   - 変化していれば「15-30秒の間」が変化区間と判定
   
3. **2周実行**して結果を確認

### フェーズ2: 中調査 (5秒刻み)
1. **変化区間を拡大**
   - 通信不安定性を考慮して前後に2秒+3秒拡大
   - 例: 15-30秒 → 13-33秒に拡大
   
2. **5秒刻みで詳細調査**
   - 拡大した区間内で5秒間隔でAPI実行
   - 直前の結果と比較して変化区間を特定
   - 例: 18-23秒が変化区間と特定
   
3. **2周実行**して結果を確認

### フェーズ3: 精密調査 (1秒刻み)
1. **変化区間をさらに拡大**
   - フェーズ2の結果に前後2秒拡大
   - 例: 18-23秒 → 16-25秒に拡大
   
2. **1秒刻みで調査**
   - 拡大した区間内で1秒間隔でAPI実行
   - 正確な更新秒数を特定
   
3. **2周実行**して結果を確認

### フェーズ4: 最終確認 (1秒刻み)
1. **最終区間設定**
   - 特定した1秒に前後2秒拡大
   - 例: 20秒が特定されたら18-22秒
   
2. **最終確認調査**
   - 1秒刻みで2周確認
   - 結果の一貫性を検証

## 📝 実装方針
- 各フェーズごとに段階的な実装
- 通信の不安定性を考慮した拡大処理
- 複数回の確認による精度向上
- 調査進捗のリアルタイム表示

## ⚙️ 技術要件
- API実行タイミングの正確な制御
- データ比較による変化検出
- フェーズ間でのデータ引き継ぎ
- 調査結果の構造化された記録
