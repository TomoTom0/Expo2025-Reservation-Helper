# スケジュール実行システム要件定義

## 基本方針
時刻指定予約実行（要求1）のみを実装。定期再試行や条件付き実行は後回し。

## UI構成

### 1. メイン画面の拡張（PavilionTab.vue）

#### スケジュールボタンの追加
- **位置**: 更新ボタンの左側
- **機能**: 押下でスケジュール設定行を表示/非表示

#### スケジュール設定行（2行目）
- **表示位置**: 検索バーや虫眼鏡ボタンがあるエリアの下に追加
- **表示条件**: スケジュールボタン押下時のみ表示

#### スケジュール設定行の要素（左から順番）
1. **実行時間入力** - 1分単位で指定可能
2. **予約間隔入力** - 現在は15秒固定、これを可変に
3. **ラベル入力** - スケジュールの識別用
4. **繰り返し回数** - 1-200回の範囲で設定
5. **有効/無効フラグボタン** - スケジュールのON/OFF
6. **保存ボタン** - 設定内容を保存
7. **ダイアログボタン** - スケジュール管理ダイアログを開く

#### 時間帯選択の拡張
- **制約解除**: スケジュール設定時は入場時間に関係なく全時間帯が押下可能
- **選択状態**: 通常の予約選択とは独立して管理

### 2. スケジュール管理ダイアログ

#### ダイアログ構成
- **サイズ**: 大きめのモーダルダイアログ
- **レイアウト**: 上部管理エリア + 左サイドバー + 右メインエリア

#### 上部管理エリア
管理用の入力欄とボタンを横並びで配置：
1. **ラベル入力**
2. **実行時間入力**
3. **繰り返し回数入力**
4. **間隔時間入力**
5. **有効/無効フラグボタン**
6. **複製編集ボタン**
   - 押下時の動作:
     - ダイアログが閉じる
     - 検索が実行される
     - 元の予約で選択されていたパビリオンの同じ時間帯があれば自動選択
     - ラベル名は元のラベル名に「_COPY」を付与
7. **保存ボタン**
8. **削除ボタン**

#### 左サイドバー（予約リスト）
既存の予約を一覧表示：
- **表示項目**: 時間、ラベル、選択時間帯個数
- **選択機能**: 項目をクリックで右側に詳細表示

#### 右メインエリア（詳細表示）
選択された予約の詳細をパビリオン検索結果風に表示：
- **スタイル**: パビリオン検索結果と同様のレイアウト
- **表示内容**: パビリオン名と時間帯をずらっと並べる
- **操作**: 時間帯の選択/選択解除が可能

## データ構造

### スケジュール予約データ
```typescript
interface ScheduledReservation {
  id: string
  label: string
  executeAt: Date                    // 実行時刻
  interval: number                   // 間隔（秒）
  maxRetries: number                // 繰り返し回数
  isEnabled: boolean                // 有効/無効
  selectedTimeSlots: {              // 選択された時間帯
    pavilionId: string
    pavilionName: string  
    timeSlot: string
    entranceDate: string
  }[]
  createdAt: Date
  updatedAt: Date
}
```

### 画面状態管理
```typescript
interface ScheduleUIState {
  showScheduleRow: boolean          // スケジュール設定行の表示状態
  showScheduleDialog: boolean       // ダイアログの表示状態
  selectedScheduleId: string | null // 左サイドバーで選択中のスケジュールID
  editingSchedule: ScheduledReservation | null // 編集中のスケジュール
}
```

## 実装の流れ

### Phase 1: UI基盤
1. PavilionTab.vueにスケジュールボタン追加
2. スケジュール設定行のUI実装
3. 時間帯選択制約の解除機能

### Phase 2: データ管理
1. ScheduledReservation型定義
2. スケジュール用ストア実装
3. localStorage連携

### Phase 3: ダイアログ実装
1. スケジュール管理ダイアログコンポーネント
2. 左サイドバーの予約リスト
3. 右メインエリアの詳細表示

### Phase 4: 実行エンジン
1. 指定時刻での自動実行機能
2. Sequential Reservationとの連携
3. 実行履歴の管理

## 注意点

- **既存機能との独立性**: 通常の予約機能に影響を与えない
- **データの永続化**: localStorageでスケジュール設定を保存
- **時刻精度**: 1分単位での実行時刻指定
- **UI統一性**: 既存のデザインシステムと統一感を保つ
